# 付費題庫的伺服器端權限控管:規劃(尚未實作)

> 這是規劃文件。**沒有價格、訂閱或付款流程,也不會在目前的 PR 實作。** 目的:將來若有付費內容,不能只靠前端鎖定。

## 1. 為什麼前端鎖定不夠
目前網站是純靜態:資料檔(`exams.js`、`explain.js`…)和程式一起送到瀏覽器,`GSAT_ACCESS`/`GSATAccess.canView()` 只是介面上的開關。任何人都能:
- 直接下載 `/gsat/exam/*.js`(網址固定、沒有登入);
- 在開發者工具裡改 `localStorage` 或 `GSAT_ACCESS`,把 `premium` 設成 true;
- 用腳本一次抓走全部題目、答案、詳解。
所以**付費內容絕對不能放在靜態檔裡**,前端的鎖只能是「提示」,真正的判斷必須在伺服器。

## 2. 先決條件:付費內容是什麼
- **考題文字的商用權利尚未確認。** 在取得大考中心的書面授權前,付費產品應只包含**原創內容**(詳解、單字詞條與發音、延伸練習、原創模擬題),考題只以「年度/題號」引用,讓使用者自己對照官方試卷。這也讓權利風險和技術設計分開。
- 若將來取得授權,考題內容同樣放在伺服器端、同一套權限機制,不改架構。

## 3. 目標架構
```
瀏覽器(靜態網站:只含程式與「免費/公開」資料)
   │  HTTPS + 登入 session(HttpOnly cookie)
   ▼
權限閘道(Cloudflare Worker 或等價的後端函式)
   ├─ 驗證登入(身分供應者)
   ├─ 查「授權表」:這個使用者有哪些 entitlement
   ├─ 通過 → 從私有儲存取內容,回傳「這一題需要的部分」
   └─ 不通過 → 403(不洩漏內容是否存在)
        │
        ▼
私有儲存(不是網站目錄):R2/資料庫/私有 bucket
   題目、答案、詳解、付費延伸練習、付費音檔
```
元件選擇(擇一,尚未決定):
- **Cloudflare**:網站已可部署在 Cloudflare Pages;Worker + KV/D1(授權表)+ R2(私有內容與音檔,以簽名網址提供)。優點:和現有部署同一家,不新增伺服器。
- **Supabase/Firebase**:身分驗證 + 資料庫列級權限(RLS)+ 邊緣函式;優點:現成的登入與資料表。
不論選哪個,原則相同。

## 4. API 設計重點(內容分段發放,答案不批量下發)
| 端點 | 行為 |
|---|---|
| `GET /api/questions?filter=…` | 回傳**清單**(年度、題號、題型、是否可看);沒有權限的題目只回「鎖定」標記,沒有內容 |
| `GET /api/q/:id` | 有權限才回題幹與選項;**不含答案與詳解** |
| `POST /api/q/:id/answer` `{choice}` | **伺服器批改**,回傳對錯、正確答案與詳解(依權限);答案只在交卷/作答後才離開伺服器 |
| `POST /api/exam/start` | 伺服器建立「考試 session」並記錄截止時間(100 分鐘由伺服器計時);交卷後才發放答案與詳解 |
| `GET /api/audio/:id` | 付費音檔回傳**短效簽名網址**(幾分鐘過期),不放在公開目錄 |
| `GET /api/me` | 回傳使用者的 entitlement,前端只用它決定畫面(UI 提示) |
- 作答紀錄、錯題本、進度改存伺服器(登入後),`localStorage` 只當離線快取;這同時是付費功能的資料。
- **免費層**:免費與公開的題目(如原創題)維持現在的靜態資料,不需登入;付費層才走 API。

## 5. 授權模型
- `users(id, email…)`、`entitlements(user_id, scope, valid_from, valid_to, source)`;`scope` 例如 `year:115`、`pack:vocab-explanations`、`all`。
- 與目前前端的 `GSAT_ACCESS`(`byYear`/`byQuestion`/`premium`)對應:伺服器端用同樣的規則判斷,前端的 `GSATAccess.canView` 改成讀 `/api/me` 的結果,**只負責畫面**。
- 付款(未來):由付款服務的 webhook 寫入 `entitlements`,前端永遠不能自己寫。目前不做價格或付款。
- 後台:人工發放/撤銷授權、查看使用紀錄。

## 6. 防護與誠實的限制
- 做得到:未登入或沒有授權時**拿不到內容**;不能用改前端變數解鎖;不能一次下載整個題庫;答案不會在作答前出現;簽名網址會過期。
- 做不到(需要誠實說明):已授權使用者仍可截圖、手抄、用自動化逐題慢慢抓。對策是降低濫用:每帳號速率限制與每日題數上限、異常行為告警、浮水印(在畫面上淡淡顯示帳號)、服務條款與帳號停權;不要承諾「完全防複製」。
- 個資:最小蒐集(登入用的 email),依個資法告知用途、保存期限與刪除方式;不要把紀錄放進公開位置。
- 安全:所有端點檢查授權;CORS 只允許自家網域;不把任何金鑰放在前端;日誌不記錄內容全文。

## 8. 測試計畫
- 未登入、無授權、授權過期、有授權、越權(用別人的題目 ID)各一組:應分別得到 401/403/403/200/403。
- 打開開發者工具改 `localStorage`、`GSAT_ACCESS`:伺服器回應不變。
- 直接請求舊的靜態路徑(`/gsat/exam/exams.js`):必須是 404 或空殼。
- 作答前請求答案/詳解:必須沒有答案。
- 簽名網址過期後存取:失敗。
- 速率限制與批量抓取模擬。
- 現有 `test_deploy.py` 的「公開版沒有任何考題內容」保留為持續檢查。
